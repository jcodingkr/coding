Splay Tree (스플레이 트리)

방금 사용한 값을 루트로 끌어올리는 똑똑한 이진 탐색 트리

A smart binary search tree that pulls the value you just used up to the root

대상: 파이썬 수업 후 알고리즘·자료구조를 배우는 중·고등학생 · 선수 지식: 이진 탐색 트리(BST), 재귀
Audience: students who finished Python and are learning algorithms & data structures · Prerequisites: binary search tree (BST), recursion

1. Splay Tree란? / What is a Splay Tree?

BST는 왼쪽 < 부모 < 오른쪽 규칙을 지키는 트리입니다. 그런데 1, 2, 3, 4, 5를 순서대로 넣으면 한 줄로 길어져서 검색이 느려집니다. Splay Tree는 값을 검색·삽입·삭제할 때마다 그 노드를 루트(맨 위)로 끌어올립니다. 이 끌어올리는 동작을 splay(스플레이)라고 합니다.

A BST keeps left < parent < right. But inserting 1, 2, 3, 4, 5 in order makes a long chain and searching gets slow. A Splay Tree moves the node you search, insert or delete to the root every time. This move is called splaying.

💡 비유: 책상 위에 책을 쌓아 두고, 방금 본 책을 항상 맨 위에 올려놓는 것과 같습니다. 자주 쓰는 책은 늘 위쪽에 있어서 빨리 찾습니다.
💡 Analogy: you keep a pile of books and always put the one you just read on top. Books you use often stay near the top, so you find them fast.
특징 / Feature설명 / Description
균형 정보 없음 / No balance info색(Red-Black)이나 높이(AVL)를 저장하지 않음 / stores no color or height
자기 조정 / Self-adjusting접근할수록 구조가 스스로 바뀜 / shape changes as you access
최근 접근 빠름 / Recent = fast최근·자주 쓴 값이 루트 근처 / recent or frequent keys stay near the root
시간 / Time분할상환(amortized) O(log n), 최악 한 번은 O(n) / amortized O(log n), one op can be O(n)

3. Splay의 3가지 경우 / The 3 Cases

노드 x를 루트로 올릴 때, x의 부모(p)와 조부모(g)의 위치 관계로 경우를 나눕니다. 이 경우를 외우면 끝입니다!

To lift node x to the root, we look at the shape formed by x, its parent (p) and grandparent (g). Learn these 3 cases and you are done!

Case 1. Zig (지그) — 부모가 루트 / parent is the root

조부모가 없을 때(마지막 단계) 회전 한 번. x가 왼쪽 자식이면 오른쪽 회전, 오른쪽 자식이면 왼쪽 회전.

No grandparent (the final step): one rotation. Left child → right rotation; right child → left rotation.

Case 2. Zig-Zig (지그-지그) — 같은 방향 일직선 / same-direction line

x와 p가 둘 다 왼쪽 자식(또는 둘 다 오른쪽). 먼저 조부모 g를 회전, 그다음 부모 p를 회전합니다. 순서가 중요합니다!

x and p are both left children (or both right). Rotate the grandparent g first, then the parent p. Order matters!

⚠️ 흔한 실수: p부터 두 번 돌리면 일반 "회전 후 올리기"가 되어 분할상환 성능 보장이 깨집니다. 꼭 g → p 순서!
⚠️ Common mistake: rotating p twice gives the naive "move-to-root" and loses the amortized guarantee. Always g → p!

Case 3. Zig-Zag (지그-재그) — 꺾인 모양 / bent shape

p는 왼쪽 자식인데 x는 오른쪽 자식(또는 반대). x를 두 번 연속 위로 회전합니다: 먼저 p 쪽, 다음 g 쪽.

p is a left child but x is a right child (or the reverse). Rotate x upward twice: first around p, then around g.

경우 / Case모양 / Shape동작 / Action
Zigg 없음 / no gx 회전 1번 / rotate x once
Zig-Zigx–p–g 일직선 / straightg 회전 → p 회전 / rotate g, then p
Zig-Zagx–p–g 꺾임 / bentx 회전 → x 회전 / rotate x, then x

4. 연산별 예제 / Operations with Examples

4-1. 검색 / Search (5 찾기)

검색은 일반 이진 탐색 트리와 동일하게 루트에서 시작하여 크기를 비교하며 내려갑니다.
• 검색 성공 시: 찾으려는 목표 노드에 도달하면 탐색을 멈춥니다. 이후 해당 노드를 스플레이 연산을 통해 루트로 이동시킵니다.
• 검색 실패 시: 찾는 값이 트리에 없어 NULL에 도달하면 탐색이 끝납니다. 이때는 방문했던 가장 마지막 노드(NULL의 부모 노드)를 스플레이하여 루트로 이동시킵니다.

BST처럼 5를 찾고, 찾은 노드를 splay합니다. 아래는 깊이 3인 5를 올리는 과정입니다: Zig-Zig 한 번(x=5, p=10, g=20) 후, 남은 부모 30에서 Zig.

Find 5 like a normal BST, then splay it. Here 5 is at depth 3: one Zig-Zig (x=5, p=10, g=20), then a final Zig with the remaining parent 30.

결과: 5가 루트가 되었고, 중간 경로(10, 20, 30)는 아래로 모여 트리가 짧아졌습니다. 중위 순회는 그대로 5, 10, 20, 30, 40이므로 BST 규칙이 유지됩니다.

Result: 5 is the root and the path (10, 20, 30) got shorter. The in-order sequence is still 5, 10, 20, 30, 40, so the BST rule holds.

💡 못 찾아도 splay합니다! 마지막으로 방문한 노드(실패 직전 노드)를 루트로 올립니다.
💡 Even a failed search splays: the last visited node becomes the root.

4-2. 삽입 / Insert

① BST처럼 삽입 → ② 새 노드를 splay. 먼저 10, 20, 30을 차례로 넣어 봅니다.

① Insert like a BST → ② splay the new node. First, insert 10, 20, 30 in order.

항상 마지막에 넣은 값(30)이 루트입니다. 이번에는 35를 삽입하면 Zig-Zag가 일어납니다 (x=35, p=40, g=30).

The most recent key (30) is always the root. Now insert 35: a Zig-Zag happens (x=35, p=40, g=30).

4-3. 삭제 / Delete (20 삭제)

① 지울 값을 splay → ② 루트를 제거(왼쪽 L, 오른쪽 R 두 트리) → ③ L의 최댓값을 splay로 루트에 올림 → ④ 그 루트의 오른쪽에 R을 붙임.

① Splay the key → ② remove the root (left tree L, right tree R) → ③ splay the max of L to L's root → ④ attach R as its right child.

여기서는 L={10}이라 10이 이미 L의 최댓값이므로 바로 R을 붙입니다.

Here L={10}, so 10 is already L's max and R attaches directly.

5. 파이썬 구현 / Python Implementation

재귀 방식입니다. splay(root, key)는 key(또는 key를 찾다 만난 마지막 노드)를 루트로 올려 새 루트를 돌려줍니다.

A recursive version. splay(root, key) brings key (or the last node on the search path) to the top and returns the new root.

class Node:
    def __init__(self, key):
        self.key = key
        self.left = self.right = None

def rotate_right(x):             # 오른쪽 회전 / right rotation
    y = x.left
    x.left, y.right = y.right, x
    return y

def rotate_left(x):              # 왼쪽 회전 / left rotation
    y = x.right
    x.right, y.left = y.left, x
    return y

def splay(root, key):
    if root is None or root.key == key:
        return root
    if key < root.key:                       # 왼쪽 / go left
        if root.left is None:
            return root
        if key < root.left.key:              # Zig-Zig
            root.left.left = splay(root.left.left, key)
            root = rotate_right(root)         # g 먼저 / g first
        elif key > root.left.key:            # Zig-Zag
            root.left.right = splay(root.left.right, key)
            if root.left.right:
                root.left = rotate_left(root.left)
        return rotate_right(root) if root.left else root   # p (Zig)
    else:                                     # 오른쪽 / go right
        if root.right is None:
            return root
        if key > root.right.key:             # Zig-Zig
            root.right.right = splay(root.right.right, key)
            root = rotate_left(root)
        elif key < root.right.key:           # Zig-Zag
            root.right.left = splay(root.right.left, key)
            if root.right.left:
                root.right = rotate_right(root.right)
        return rotate_left(root) if root.right else root

def search(root, key):           # 검색 / search
    return splay(root, key)      # root.key == key 이면 찾음 / found if equal

def bst_insert(r, key):
    if r is None: return Node(key)
    if key < r.key: r.left = bst_insert(r.left, key)
    elif key > r.key: r.right = bst_insert(r.right, key)
    return r

def insert(root, key):           # 삽입 = BST 삽입 + splay
    return splay(bst_insert(root, key), key)

def delete(root, key):
    if root is None: return None
    root = splay(root, key)
    if root.key != key: return root          # 없음 / not found
    if root.left is None: return root.right
    L = splay(root.left, key)    # key가 L의 모든 값보다 크므로 최댓값이 루트로!
    L.right = root.right         # key is larger than all in L, so L's max rises
    return L

def preorder(n):                 # 확인용 / for checking
    return [] if n is None else [n.key] + preorder(n.left) + preorder(n.right)

root = None
for k in [10, 20, 30]:
    root = insert(root, k)
print(preorder(root))            # [30, 20, 10]  → 30이 루트 / 30 is the root
root = search(root, 10)
print(preorder(root))            # [10, 30, 20]

6. 시간 복잡도 / Time Complexity

연산 / Op분할상환 / Amortized최악 1회 / Worst single
Search / Insert / DeleteO(log n)O(n)

"분할상환"은 연산 m번의 총 시간을 m으로 나눈 평균이 O(log n)이라는 뜻입니다. 느린 연산(긴 줄 풀기)이 한 번 있으면, 그 덕분에 트리가 짧아져 다음 연산들이 빨라집니다.

"Amortized" means the average over m operations is O(log n). One slow operation (unrolling a long chain) shortens the tree and makes later operations fast.

장점 / Pros단점 / Cons
Splay구현 간단, 추가 메모리 없음, 최근 값 빠름 / simple, no extra field, recent keys fast검색도 트리를 바꿈, 한 번이 느릴 수 있음 / search modifies tree, one op can be slow
Red-Black / AVL최악도 O(log n) / worst case O(log n)색·높이 저장, 구현 복잡 / extra field, harder code

7. 연습문제 / Practice

문제 1. 빈 트리에 1, 2, 3, 4를 차례로 삽입한 최종 트리를 그려 보세요.

Q1. Insert 1, 2, 3, 4 in order into an empty tree. Draw the final tree.

정답 / Answer

삽입할 때마다 새 값이 루트로 올라가므로 4가 루트이고 왼쪽으로 한 줄입니다.

Each new key becomes the root, so 4 is the root with a left chain.

문제 3. Splay Tree에서 같은 값을 계속 검색하면 왜 빠를까요? 힌트: 첫 검색 후 그 값의 위치는?

Q3. Why is repeatedly searching the same key fast? Hint: where is the key after the first search?

정답 / Answer

첫 검색 후 루트에 있어서 다음부터는 비교 1번으로 찾습니다.

After the first search it is the root, so each next search needs just one comparison.

8. 정리 / Summary

접근한 노드를 splay로 루트에 올린다 · 3가지 경우: Zig / Zig-Zig(g→p) / Zig-Zag · 삽입 = BST 삽입 + splay · 삭제 = splay + L의 최댓값 splay + R 연결 · 분할상환 O(log n)
Splay the accessed node to the root · 3 cases: Zig / Zig-Zig (g→p) / Zig-Zag · Insert = BST insert + splay · Delete = splay + splay max of L + attach R · Amortized O(log n)
