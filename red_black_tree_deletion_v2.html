Red-Black Tree 삭제 (Deletion)

삭제가 왜 어려운지, 그리고 "검정 하나가 모자란 자리"를 어떻게 채우는지 숫자 노드 그림으로 단계별로 배웁니다.
Learn step by step, using numeric node diagrams, why deletion is difficult and how to fix a position that is missing one black node.

0. 먼저 알아둘 규칙 (Properties / 기본 속성)

  1. 모든 노드는 빨강(Red) 또는 검정(Black)이다. Every node is either red or black.
  2. 루트(root)는 검정이다. The root node is black.
  3. 빨간 노드의 자식은 반드시 검정이다. (빨강이 연속되면 안 됨) A red node must have black children (no two consecutive red nodes).
  4. 모든 NIL(빈 자리)은 검정이다. Every NIL (empty) leaf is black.
  5. 어떤 노드에서 출발해 NIL까지 가는 모든 길에서 검정 노드 수가 같다. (black height) Every path from a node to a NIL leaf contains the same number of black nodes (black height).
RedBlackDB = Double Black (검정이 하나 모자란 자리)

삭제가 어려운 이유는 5번 규칙 때문입니다. 검은 노드 하나를 빼면 그쪽 길만 검정이 하나 줄어듭니다. 그 빈자리를 DB로 표시하고, 주변 노드의 색을 바꾸거나 회전해서 빚을 갚는 것이 삭제의 핵심입니다.
Deletion is difficult because of Property 5. Removing a black node reduces the black-node count on only the affected paths. We mark that position as DB and restore balance by recoloring nearby nodes or performing rotations.

1. 삭제 순서 / Steps (Deletion Steps)

1단계. 일반 이진 탐색 트리(BST)처럼 지운다
Step 1. Delete the node as in a Binary Search Tree (BST).

  • 자식이 없으면 (leaf) 그냥 제거
    If the node has no children (a leaf), simply remove it.
  • 자식이 1개면 그 자식이 올라옴
    If the node has one child, promote that child.
  • 자식이 2개면 오른쪽 서브트리의 가장 작은 값 (successor)을 복사해 오고, 그 successor 노드를 대신 지움
    If the node has two children, copy the smallest value in the right subtree (the successor) into its position, then remove the successor node.

그래서 실제로 트리에서 사라지는 노드는 항상 자식이 0개 또는 1개입니다.
Therefore, the node physically removed from the tree always has at most one child.

위 그림은 자식이 둘인 10을 지우는 경우입니다. 오른쪽에서 가장 작은 15의 값을 10 자리에 복사하고, 원래 15 노드(빨강 leaf)를 지웁니다. 지워진 것이 빨강이라 바로 끝납니다.
The diagram shows how to delete 10, which has two children. Copy the smallest value in the right subtree, 15, into the position of 10, then remove the original 15 node (a red leaf). Since the removed node is red, the operation ends immediately.

2단계. 실제로 지워진 노드의 색을 본다
Step 2. Check the color of the node that was physically removed.

상황처리
지워진 노드가 빨강검정 개수가 변하지 않으므로 그대로 끝
지워진 노드가 검정이고, 올라온 자식이 빨강그 자식을 검정으로 칠하고 끝
지워진 노드가 검정이고, 올라온 자리가 NIL(또는 검정)그 자리가 DB가 됨 → 3단계 (Case 1~4)

2. Double Black 이란? (What Is Double Black?)

검정 노드를 지우면 그 길은 검정이 하나 모자랍니다. 이 모자란 한 개를 "DB가 검정 두 개짜리 노드인 것처럼" 취급해서 기억해 두는 것이 Double Black입니다. 목표는 DB를 없애는 것이며, 방법은 두 가지입니다.
When a black node is removed, the affected path is short by one black node. Double Black (DB) is a way to represent this deficit, as if the position had an extra black count to be resolved. The goal is to eliminate DB in one of two ways:

  • 검정을 어딘가에서 하나 가져온다 (회전 + 색 변경)
  • DB를 부모 쪽으로 한 칸 올려서 나중에 해결한다

DB 자리의 부모를 P, 형제를 S(sibling), S의 자식을 조카(nephew)라 부릅니다. DB가 왼쪽에 있을 때 S의 오른쪽 자식이 먼 조카 (far nephew), 왼쪽 자식이 가까운 조카 (near nephew)입니다. DB가 오른쪽이면 좌우가 반대입니다.
Let P be the parent of DB, S its sibling, and the children of S its nephews. When DB is on the left, S’s right child is the far nephew and its left child is the near nephew. The directions are reversed when DB is on the right.

3. 네 가지 케이스 / Cases (The Four Cases)

S의 색과 조카의 색을 보고 아래 네 가지 중 하나를 고릅니다.
Choose one of the four cases below based on the color of sibling S and the colors of its nephews.

Case 1. 형제 S가 빨강 (Sibling S is Red)

P 기준으로 회전(rotation)하고 P와 S의 색을 맞바꿉니다. DB의 새 형제는 검정이 되므로 Case 2, 3, 4 중 하나로 넘어갑니다. 이 케이스는 해결이 아니라 "상황을 바꾸는" 단계입니다.
Rotate around P and swap the colors of P and S. The new sibling of DB becomes black, so proceed to Case 2, 3, or 4. This case transforms the configuration; it does not resolve DB by itself.

Case 2. S가 검정이고 조카가 모두 검정 (Sibling S and Both Nephews Are Black)

S를 빨강으로 칠합니다. 형제도 검정 하나를 내놓아 양쪽이 같아지게 하는 것입니다. P가 빨강이면 검정으로 칠하고 끝납니다. P가 검정이면 DB가 P로 올라가서 다시 Case 1~4를 봅니다. 루트까지 올라가면 DB는 그냥 사라집니다.
Recolor S to red. The sibling gives up one black node so both sides match. If P is red, recolor P black and finish. If P is black, move DB up to P and examine Cases 1–4 again. If DB reaches the root, remove DB.

Case 3. S 검정, 먼 조카 검정, 가까운 조카 빨강 (Black Sibling, Black Far Nephew, Red Near Nephew)

S 기준으로 DB에서 먼 방향으로 회전하고 S와 가까운 조카의 색을 맞바꿉니다. 결과가 Case 4 모양이 됩니다.
Rotate around S in the direction away from DB, then swap the colors of S and the near nephew. This transforms the tree into the Case 4 configuration.

Case 4. S 검정, 먼 조카 빨강 (Black Sibling, Red Far Nephew)

P 기준으로 회전합니다. S는 P의 색을 가져가고, P와 먼 조카는 검정으로 칠합니다. 먼 조카의 빨강이 검정으로 바뀌면서 모자란 검정 하나를 채우므로 DB가 사라지고 삭제가 끝납니다.
Rotate around P. S takes P’s original color, while P and the far nephew are recolored black. The far nephew’s red becomes black and supplies the missing black node, eliminating DB and completing deletion.

외우는 요령: Case 1은 "형제가 빨강이면 검정으로 바꿔 놓고 다시 본다", Case 2는 "형제도 같이 빨강이 되고 빚은 부모에게 넘긴다", Case 3은 "조카를 먼 쪽으로 옮겨 Case 4로 만든다", Case 4는 "먼 조카의 빨강을 검정으로 바꿔 빚을 갚는다".

시간 복잡도 (time complexity)는 O(log n)입니다. Case 2만 위로 반복될 수 있고, 회전은 삭제 한 번에 최대 3번입니다.
The time complexity is O(log n). Only Case 2 can repeat while moving upward, and a single deletion requires at most three rotations.

5. 의사코드 (Pseudocode)

fix_double_black(X):
    while X is not root and X is double black:
        S = sibling(X)
        if S is red:                          # Case 1
            swap_color(parent, S)
            rotate(parent toward X)           # X's new sibling is black
            continue
        if both children of S are black:      # Case 2
            S.color = red
            if parent is red:
                parent.color = black
                break                         # done
            X = parent                        # DB moves up
        else:
            if far child of S is black:       # Case 3
                near_child.color = black
                S.color = red
                rotate(S away from X)
                S = sibling(X)
            S.color = parent.color            # Case 4
            parent.color = black
            S.far_child.color = black
            rotate(parent toward X)
            break
    root.color = black
